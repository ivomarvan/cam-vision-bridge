# Epic Plan: E010 — Spike: WebRTC aiortc ↔ mobil přes PeerJS

## Epic Goal

Spike (typ `spike`, `070-project-management.mdc`) odpovídá na otázku z `roadmap.md`:
**Naváže Python (`aiortc` + minimální PeerJS klient) WebRTC DataChannel s Chrome na Androidu
přes veřejný PeerJS cloud a zvládne přenášet JPEG snímky 640×480 dostatečně rychle?**
Výstupem je měřicí nástroj (Python echo peer + měřicí stránka + analýza), tabulka výsledků,
`README.md` a ADR-001, které potvrdí transport z DECISIONS #2, nebo doporučí fallback.

- **Stav:** plán schválen Humanem 2026-11-21 (FE.2).
- **Větev:** `spike/webrtc-peerjs-aiortc` — Human pověřil Plannera jejím lokálním
  založením (`git switch -c`); commit/push jen na trigger frázi (`020-git.mdc`).
- **Adresář:** `experiments/2026-11-webrtc-peerjs-aiortc/` (`060-project-structure.mdc`).
- **Kandidáti:** jediný transport (DataChannel přes PeerJS cloud); porovnávají se
  konfigurace (kvalita JPEG, počet snímků „na cestě“, velikost části) a zařízení.
- **Metriky:** úspěch spojení a čas navázání; typy ICE kandidátů (host / mDNS / srflx /
  relay); dosažené FPS; medián a p95 round-trip latence; průměrná velikost snímku; doba
  dekódování JPEG v Pythonu; chování zprávy větší než ~64 KB (bez dělení).
- **Zařízení:** Chrome desktop na stejném PC (baseline, zvládne Coder), Chrome na Androidu
  (povinné, měří Human), Safari na iOS (volitelné).
- **Vstup pro rozhodnutí (ne automatický práh):** cílový rozpočet z `spec.md` § 6 — ≥ 10 FPS
  a medián latence ≤ 200 ms end-to-end; samotný transport by měl být výrazně pod tím.

### Binární zpráva se snímkem (mobil → PC)

```
[uint32 big-endian: header_len][header: UTF-8 JSON, header_len bytes][payload: JPEG bytes of this part]
```

Hlavička: `{"t": "frame", "run_id": str, "frame_id": int, "part": int, "parts": int, "total_bytes": int}`.
`part` je 0-based; `total_bytes` je velikost celého JPEG. `chunk_bytes = 0` znamená „bez
dělení“ (celý JPEG v jedné zprávě, `parts = 1`).

**Limity na straně Pythonu (nedůvěryhodný vstup):** `header_len ≤ 4096`; `1 ≤ parts ≤ 256`;
`0 ≤ part < parts`; `total_bytes ≤ 8 MiB`; součet payloadů = `total_bytes`; všechny části
snímku mají shodné `parts` a `total_bytes`; nekompletní snímek starší než 2 s se zahodí.
Porušení → zahodit, zalogovat `WARNING`, poslat `error`, spojení nechat běžet.

### Textové JSON zprávy přes DataChannel

| Směr | `t` | Pole |
|---|---|---|
| mobil → PC | `run_start` | `run_id`, `config{mode, width, height, quality, in_flight, chunk_bytes, duration_s}`, `device_ua`, `connect_ms`, `ice{local_type, remote_type, protocol}` |
| mobil → PC | `rtt` | `run_id`, `frame_id`, `rtt_ms` |
| mobil → PC | `run_end` | `run_id`, `frames_sent`, `frames_echoed` |
| PC → mobil | `echo` | `run_id`, `frame_id`, `bytes`, `parts`, `decode_ms` |
| PC → mobil | `error` | `reason`, volitelně `frame_id` |

`mode` ∈ `synthetic` | `camera`. `rtt_ms` = čas od odeslání první části snímku do přijetí
jeho `echo` (`performance.now()`). `decode_ms` = doba `cv2.imdecode` v Pythonu.

### PeerJS 1.5.4 — `OFFER` (DECISIONS #6)

Připnutá verze stránky je PeerJS **1.5.4**. `OFFER.payload` pro data spojení obsahuje
`sdp`, `type`, `connectionId`, `metadata`, `label`, `reliable`, `serialization`. Pole
`browser` v něm **není** (starší lokální `peerjs.min.js` ho měla; Python ho nevyžaduje).
`ANSWER` z Pythonu smí `browser: "aiortc"` obsahovat; prohlížeč ho nečte.

### CSV výstupy (zapisuje T010, čte T030)

- `results/runs.csv` (jeden řádek na běh, hlavička jednou): `run_id, started_at, device_ua,
  mode, width, height, quality, in_flight, chunk_bytes, duration_s, connect_ms,
  ice_local_type, ice_remote_type, ice_protocol, frames_sent, frames_echoed`.
  Řádek se zapíše při `run_end` (`started_at` = ISO 8601 UTC z času přijetí `run_start`).
- `results/frames/<run_id>.csv`: `frame_id, bytes, parts, rtt_ms, decode_ms`. Řádek se
  zapíše při přijetí `rtt` (`bytes`, `parts`, `decode_ms` si peer pamatuje z echo).

### Matice měření (výchozí, spouští stránka jedním tlačítkem)

`quality ∈ {0.6, 0.8}` × `in_flight ∈ {1, 2}` × `chunk_bytes ∈ {16384, 61440}` = 8 běhů po
20 s, 640×480, cílová horní mez 30 FPS; potom **sonda** `quality 0.8, in_flight 1,
chunk_bytes 0` (bez dělení — může spojení shodit, proto poslední).
